# Troubleshooting Summary Preference

Whenever completing a troubleshooting task, always provide the final summary in the following high-level format (focusing on plain-language concepts rather than internal API routes/endpoints):

### What the Issue Was
- Clear, plain-language bullet points explaining the root cause, background behavior, and symptom impact.

### How It Was Fixed
- Clear, plain-language bullet points detailing the implemented solutions, fallback safeguards, and administrative instructions.
